# KAPS — личный архив крышек от снюса

**KAPS** — полноценное веб-приложение для коллекционирования крышек: фотографируете крышку, OCR читает бренд и вкус, сервер сверяет находку с каталогом и определяет редкость. Коллекция, достижения, уровни, статистика, темы, публичный профиль, Telegram-бот и админ-консоль — всё связано с реальной базой PostgreSQL.

> Каждая крышка — часть твоей коллекции.

## Что умеет KAPS

- **Добавление только по реальному фото.** Камера или загрузка файла → превью → OCR/vision → проверка по каталогу → редактируемое описание → сохранение. Ручного добавления «из воздуха» нет.
- **Защита от повторов.** SHA-256 и perceptual hash не дают дважды добавить одну и ту же фотографию или почти одинаковый кадр.
- **Редкость из каталога.** `Common`, `Uncommon`, `Rare`, `Epic`, `Legendary`, `Mythic` и `Undetermined` определяет сервер по модели крышки. Клиент и AI не могут назначить редкость.
- **Коллекция.** Сетка карточек, поиск по названию, фильтр по производителю, фильтр Legendary/Mythic, сортировка по редкости и дате, страница крышки.
- **Достижения.** First Cap, Collector, Experienced, Master Collector, Legend Hunter, Myth Hunter, Brand Explorer, Perfectionist, Rare Collector, Globetrotter. Даты открытия и уведомления.
- **Уровни и XP.** Уровень растёт от количества крышек, редкостей и достижений.
- **Статистика.** Редкости, производители, прогресс каталога, активность по дням, средние показатели.
- **Профиль.** Имя и аватар из Telegram, username, уровень, редкости, достижения, дата регистрации, приватность и публичная страница `/u/[slug]`.
- **Темы.** Light, Dark, Midnight, Graphite, Aurora и полностью своя палитра. Настройки хранятся в профиле и применяются на всех устройствах.
- **Telegram-вход.** Login Widget и Mini App с проверкой подписи на сервере. Токен бота никогда не попадает в браузер.
- **Telegram-бот.** Профиль, последние крышки, достижения, поддержка, создание обращений и ответы, активация роли Support по ключу, команды для staff.
- **Поддержка.** Обращения, переписка, статусы, назначение на сотрудника, уведомления в сайте и Telegram.
- **Админ-консоль.** Пользователи и роли, коллекции и фото, производители, модели, каталог, достижения, обращения, аналитика, исправление OCR.
- **Адаптивность.** Верхняя навигация на десктопе и нижняя панель на мобильных.

## Технологии

| Слой | Технология |
| --- | --- |
| Framework | Next.js 16.4 (App Router, Turbopack), React 19.3, TypeScript |
| UI | Tailwind CSS 4.3, Framer Motion, Lucide, собственный дизайн-система |
| База | PostgreSQL + Prisma 6.19 |

| Vision (опция) | Любой OpenAI-совместимый chat/completions с изображением |
| Telegram | Grammy (бот), Login Widget, Mini App initData |
| Хранилище | Локальная папка или S3-совместимое (MinIO, R2, AWS S3) |

- Node.js **20.9+** (рекомендуется 22 LTS или новее);
- PostgreSQL **14+**;
- npm;
- для Telegram-входа — публичный HTTPS-домен (localhost подходит только для dev-входа).

## Быстрый старт

```bash
# 1. Зависимости
npm install

# 2. Конфигурация
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env

# 3. Заполните .env (минимум DATABASE_URL и SESSION_SECRET)

# 4. Схема и демо-данные
npm run db:push
npm run seed

# 5. Веб-приложение
npm run dev
```

Откройте `http://localhost:3000`.

Для локальной проверки без Telegram включите в `.env`:

```env
ENABLE_DEV_LOGIN="true"
```

Тогда на `/login` появится блок локального входа: **Admin** и **Collector**. Это работает только при `NODE_ENV !== "production"`. В production dev-вход отключён на уровне API, даже если переменная забыта.

Запуск сайта и бота одновременно:

```bash
npm run dev:all
```

Или отдельно:

```bash
npm run dev   # сайт
npm run bot   # Telegram-бот
```

## Переменные окружения

Полный шаблон — в `.env.example`. Значения с пробелами и спецсимволами заключайте в кавычки.

### Основное

| Переменная | Обязательно | Описание |
| --- | --- | --- |
| `DATABASE_URL` | да | Строка PostgreSQL, например `postgresql://postgres:postgres@localhost:5433/kaps?schema=public` |
| `APP_URL` | да | Публичный адрес сайта без слэша на конце. В dev: `http://localhost:3000` |
| `SESSION_SECRET` | да | Случайная строка от 32 символов для подписи сессий |
| `SESSION_TTL_DAYS` | нет | Срок жизни сессии, по умолчанию 30 дней |

Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

### Telegram

| Переменная | Описание |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather. **Только сервер**, никогда не `NEXT_PUBLIC_*` |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | Username бота без `@` — нужен Login Widget |
| `TELEGRAM_LOGIN_MAX_AGE_SECONDS` | Максимальный возраст подписи, по умолчанию 86400 |
| `ADMIN_TELEGRAM_IDS` | Telegram ID администраторов через запятую |
| `SUPPORT_TELEGRAM_IDS` | Telegram ID сотрудников поддержки через запятую |
| `SUPPORT_CHAT_ID` | Куда бот присылает новые обращения (чат или канал) |

### Поддержка

| Переменная | Описание |
| --- | --- |
| `SUPPORT_KEY_HASH` | Только scrypt-хеш ключа, см. [Ключ поддержки](#ключ-поддержки) |
| `SUPPORT_KEY_MAX_ATTEMPTS` | Попыток до блокировки, по умолчанию 5 |
| `SUPPORT_KEY_LOCK_MINUTES` | Длительность блокировки, по умолчанию 60 минут |

### Загрузки и хранилище

| Переменная | Описание |
| --- | --- |
| `UPLOAD_DIR` | Локальная папка файлов, по умолчанию `./storage/uploads` |
| `MAX_UPLOAD_MB` | Максимальный размер фото, по умолчанию 12 МБ |
| `S3_ENDPOINT` | Endpoint S3-совместимого хранилища; пусто — локально |
| `S3_REGION` | Регион |

| `S3_ACCESS_KEY_ID` | Access key |

S3 включается только когда заполнены **все** обязательные поля. В остальных случаях используется локальная папка.

| --- | --- |

## База данных и демо-коллекция

Создайте базу:

```sql
CREATE DATABASE kaps;
```

Укажите её в `DATABASE_URL` и примените схему:

```bash
npm run db:push       # синхронизировать schema.prisma с базой
npm run seed          # каталог, достижения и демо-коллекция
```

`npm run seed` идемпотентен:

- 12 производителей и 52 модели крышек;
- 10 определений достижений;
- демо-пользователь **KAPS Archive** с публичной коллекцией `/u/demo`;
- демо-фото генерируются локально через Sharp и хранятся в `public/demo`;
- реальные коллекции пользователей не удаляются и не смешиваются с демо-данными благодаря флагу `isDemo`.

Для миграций в командной разработке:

```bash
npm run db:migrate    # prisma migrate dev
npm run db:generate   # prisma generate
npm run db:studio     # Prisma Studio
```

> **Сброс только локальной базы:** `npx prisma db push --force-reset && npm run seed`. Команда удалит все данные.

## Telegram: вход и бот

### 1. Создайте бота

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Получите токен и username.
3. Заполните:
   ```env
   TELEGRAM_BOT_TOKEN="123456789:AA..."
   NEXT_PUBLIC_TELEGRAM_BOT_USERNAME="your_bot"
   ```

### 2. Настройте домен Login Widget

В @BotFather: `/setdomain` → выберите бота → укажите домен сайта **без** `https://` (например, `kaps.example.com`).

Telegram Login Widget требует HTTPS и зарегистрированный домен. Для локальной разработки используйте dev-вход.

### 3. Mini App (опционально)

В @BotFather: `/newapp` → выберите бота → задайте название, описание, иконку и URL приложения (`https://kaps.example.com`). Mini App автоматически передаёт `initData`, который KAPS проверяет по HMAC-подписи. Fallback на Login Widget остаётся.

### 4. Администраторы и поддержка

Узнайте свой Telegram ID через @userinfobot и добавьте:

```env
ADMIN_TELEGRAM_IDS="123456789"
SUPPORT_TELEGRAM_IDS="987654321,555555555"
SUPPORT_CHAT_ID="-1001234567890"
```

При первом входе роль из env применяется автоматически. Понижение роли через env не происходит — только повышение; менять роли можно в админ-панели.

### 5. Запустите бота

```bash
npm run bot
```

Бот сам вызывает `getMe`, регистрирует команды и начинает polling. Запускайте **ровно один экземпляр** бота: Telegram не поддерживает несколько polling-процессов с одним токеном.

Меню и команды:

- `/start` — главное меню;
- `/profile` — профиль, уровень, редкости;
- `/collection` — последние крышки;
- `/achievements` — достижения и следующие цели;
- `/support` — создать обращение или открыть переписку;
- `/tickets` — очередь обращений для Support/Admin;
- `/reply ID текст` — ответ staff;
- `/resolve ID` — закрыть обращение;
- `/help`, `/cancel`.

Пользователь, впервые написавший боту, автоматически создаётся в базе. Отдельная регистрация не нужна.

## Ключ поддержки

Ключ нужен, чтобы пользователь мог сам активировать роль **Support**. На сервере хранится **только scrypt-хеш**, открытый ключ нигде не сохраняется.

Сгенерируйте хеш:

```bash
npm run support:hash -- "ваш-длинный-секретный-ключ"
```

Скрипт выведет строку формата:

```
scrypt:<salt>:<hash>
```

Поместите её в `.env`:

```env
SUPPORT_KEY_HASH="scrypt:..."
```

Двоеточия выбраны специально: Next.js раскрывает `$переменные` в `.env`, из-за чего формат с `$` мог незаметно ломаться. Старый формат `scrypt$...` всё ещё поддерживается для совместимости, но новый использовать безопаснее.

Активация:

- на сайте: **Настройки → Стать поддержкой**;
- в боте: **🤝 Стать поддержкой**.

Защита:

- неверные попытки считаются в базе;
- после `SUPPORT_KEY_MAX_ATTEMPTS` попыток вход блокируется на `SUPPORT_KEY_LOCK_MINUTES`;
- успешная активация сбрасывает счётчик;
- факт активации попадает в события и уведомления.

## Распознавание крышек

Пайплайн `/api/scans`:

1. Проверка авторизации, origin, лимита сканирований (40/час на пользователя).
2. Sharp: поворот по EXIF, ограничение размера, JPEG-нормализация, удаление метаданных.
3. Проверка минимального разрешения (240 px) и максимального размера файла.
4. SHA-256 + perceptual hash; точные и почти одинаковые дубликаты отклоняются.
5. Tesseract запускается на двух вариантах изображения: обычный контраст и бинаризация.
6. Каждый вариант сверяется с каталогом: алиасы, ключевые слова, производитель, модель.
7. Выбирается лучший результат; при наличии `OPENAI_API_KEY` vision вызывается **только если** локальный OCR не нашёл каталог.
8. Редкость берётся из модели каталога на сервере. Неизвестная модель → `UNDETERMINED`.
9. Скан сохраняется на 24 часа; подтверждение создаёт элемент коллекции и помечает скан использованным.

Практические советы:

- фотографируйте крышку сверху, целиком, без сильных бликов;
- текст должен занимать заметную часть кадра;
- тёмные крышки лучше снимать при рассеянном свете;
- при первом запуске Tesseract скачивает языковые данные в `OCR_CACHE_DIR` — нужен интернет и права на запись;
- если крышка не распознана, приложение не даёт добавить её вручную: сделайте новое фото.

Vision **не является источником редкости**. Он лишь добавляет текст, который затем сверяется с каталогом. При включённом vision нормализованное фото отправляется выбранному провайдеру — учитывайте это в политике приватности.

## Хранение изображений

По умолчанию:

```
storage/uploads/scans/<userId>/<uuid>.jpg
storage/uploads/items/<userId>/<uuid>.jpg
```

Файлы не отдаются напрямую. Доступ идёт через `/api/media/[...key]`:

- владелец видит свои файлы;
- staff видит файлы для модерации;
- фото публичного профиля доступны без входа;
- приватные фото возвращают `404`, чтобы не раскрывать существование файла.

Для S3 заполните все `S3_*` переменные. Бакет должен быть приватным: приложение само выдаёт доступ через API. Папка `storage/` и `.env` исключены из git.

## Роли и админ-панель

| Роль | Возможности |
| --- | --- |
| `USER` | Своя коллекция, сканы, достижения, темы, обращения |
| `SUPPORT` | Всё выше + все обращения, ответы, статусы, очередь в боте |
| `ADMIN` | Всё выше + пользователи, роли, каталог, достижения, фото, аналитика, OCR-коррекция |

Админ-панель: `http://localhost:3000/admin` (вкладки через hash: `#overview`, `#users`, `#items`, `#catalog`, `#achievements`, `#tickets`, `#analytics`, `#ocr`).

Возможности администратора:

- менять роли и видеть активность пользователей;
- редактировать карточки крышек и исправлять распознанный текст;
- управлять производителями и моделями, архивировать используемые записи;
- менять редкость модели — она пересчитывается у всех связанных крышек;
- создавать и редактировать достижения, запускать пересчёт;
- читать обращения и отвечать от имени поддержки;
- смотреть аналитику без demo-данных;
- открывать фото для проверки OCR.

Все защищённые API проверяют сессию и роль на сервере. Клиентская навигация не является защитой.

## Достижения и редкости

Редкости (отображаются английскими названиями):

`Common → Uncommon → Rare → Epic → Legendary → Mythic`, плюс `Undetermined`, если модель не найдена.

Достижения по умолчанию:

| Достижение | Условие |
| --- | --- |
| First Cap | 1 крышка |
| Collector | 10 крышек |
| Experienced | 25 крышек |
| Master Collector | 50 крышек |
| Legend Hunter | 1 Legendary |
| Myth Hunter | 1 Mythic |
| Brand Explorer | 5 производителей |
| Perfectionist | 100 крышек |
| Rare Collector | 10 Rare |
| Globetrotter | 10 производителей |

Достижения выдаются сервером после добавления крышки или изменения каталога. Одновременно создаётся уведомление на сайте и, если у пользователя есть Telegram, сообщение в боте. Повторно достижение не выдаётся.

## Production-развёртывание

KAPS использует Node.js runtime, Sharp, Tesseract и (опционально) S3. Это **не edge-приложение**. Рекомендуется VPS, Docker-хост или платформа с постоянным диском и долгоживущими процессами.

1. **Сервер и Node.js.** Node 20.9+; для сборки нужны обычные build-зависимости.
2. **PostgreSQL.** Управляемая база или отдельный сервис. Сделайте резервные копии.
3. **Переменные.** Все значения из `.env.example`, `APP_URL` — публичный HTTPS-адрес. `ENABLE_DEV_LOGIN` не задавайте.
4. **Миграции.** На чистой базе: `npx prisma migrate deploy` (если используете миграции) или `npm run db:push`. Затем при необходимости `npm run db:seed` (осторожно: демо-данные не обязательны в production).
5. **Сборка.** `npm ci && npm run build`.
6. **Веб-процесс.** `npm start` под systemd/pm2/Docker с переменными окружения.
7. **Бот-процесс.** Отдельный процесс `npm run bot`, ровно один экземпляр.
8. **Хранилище.** Для нескольких инстансов или эфемерного диска используйте S3 и заполните `S3_*`. Локальное хранилище требует постоянного диска и одного общего пути.
9. **OCR-кэш.** Сделайте `OCR_CACHE_DIR` записываемым и сохраняйте между деплоями, чтобы не скачивать языки заново.
10. **Обратный прокси.** Nginx/Caddy с HTTPS, лимитом тела запроса не меньше `MAX_UPLOAD_MB` и разумными таймаутами для OCR (до 60 секунд).

Если сайт работает за прокси, `APP_URL` должен совпадать с внешним origin: это важно для проверки origin и ссылок бота.

## Безопасность

- `.env` содержит секреты и исключён из git. Не коммитьте его и не публикуйте хеш поддержки.
- `TELEGRAM_BOT_TOKEN` используется только на сервере. Не добавляйте префикс `NEXT_PUBLIC_` к секретам.
- Telegram-подписи Login Widget и Mini App проверяются HMAC на сервере с ограничением возраста.
- Сессии: случайный токен в HttpOnly/SameSite=Lax cookie, в базе хранится только HMAC-хеш; `Secure` включается в production.
- Смена темы, профиля, ролей, тикетов и сканов идёт через API с проверкой сессии, прав и origin.
- Редкость никогда не принимается от клиента или AI — только из каталога.
- Загрузки нормализуются Sharp, ограничены по размеру и проверяются на дубликаты.
- Доступ к изображениям проверяется по владельцу, публичности профиля и роли staff.
- Dev-вход работает только при `NODE_ENV !== "production"` и `ENABLE_DEV_LOGIN="true"`.
- Ключ поддержки хранится как scrypt-хеш; попытки ограничены и блокируются.
- Перед production смените `SESSION_SECRET`, токен бота и ключ поддержки, если они использовались в разработке.
- Регулярно обновляйте зависимости и делайте бэкапы PostgreSQL и загруженных файлов.

## Диагностика

**`P1001: Can't reach database server`**  
Проверьте, что PostgreSQL запущен, порт совпадает с `DATABASE_URL`, база создана.

**`SESSION_SECRET не настроен`**  
Добавьте секрет длиной от 16 символов (лучше 32+) в `.env` и перезапустите процесс.

**Telegram Login Widget не появляется**  
Проверьте `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`, домен в `/setdomain`, HTTPS. В dev используйте локальный вход.

**Mini App не входит**  
`initData` живёт ограниченное время; откройте приложение заново из Telegram. Убедитесь, что токен бота на сервере тот же, что у бота.

**Бот пишет `TELEGRAM_BOT_TOKEN не задан`**  
Заполните токен в `.env` и перезапустите `npm run bot`.

**`SUPPORT_KEY_HASH` не принимается**  
Сгенерируйте новое значение командой `npm run support:hash -- "ключ"` и вставьте строку `scrypt:...` целиком, в кавычках. Если после 5 ошибок сработала блокировка, подождите `SUPPORT_KEY_LOCK_MINUTES` или сбросьте запись `SupportKeyAttempt` в админке/базе.

**OCR долго запускается в первый раз**  
Tesseract скачивает языковые данные. Проверьте интернет и права на `OCR_CACHE_DIR`. Повторные запуски используют кэш.

**Крышка не распознаётся**  
Сделайте более резкое фото сверху, без бликов, с крупным текстом. Убедитесь, что модель есть в каталоге или что её алиасы/ключевые слова добавлены в админке.

**Фото 404**  
Профиль приватный, файл принадлежит другому пользователю или запись удалена. Staff видит изображения для модерации.

**Сборка падает на Sharp/Tesseract**  
Убедитесь, что платформа поддерживает Node runtime и нативные пакеты; не используйте edge runtime для API сканирования и медиа.
